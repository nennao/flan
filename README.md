# Flan

Flan (food + plan) is a personal meal planner: recipes with real nutrition, plans against daily targets. It's being
rebuilt as a Next.js / React / TypeScript app from a 2021 Flask + vanilla JS prototype.

- [GOALS.md](GOALS.md): what this project is for.
- [ROADMAP.md](ROADMAP.md): phases, current status and next action.
- [docs/LEGACY_ASSESSMENT.md](docs/LEGACY_ASSESSMENT.md): the legacy app, the agreed architecture (§9) and decisions
  (§11).

The legacy app (`flan/`, `web/`, `scripts/`, `requirements.txt`, `Procfile`, `runtime.txt`) stays in the repo as a
reference until each feature is replaced. To run it, see the assessment, §4.4.

## Requirements

- **Node.js 24.**
- **pnpm**, via corepack: `corepack enable pnpm`. The version is pinned in `package.json` (`packageManager`), and
  corepack uses it automatically. Corepack ships with Node 24; on Node 25+, run `npm i -g corepack` first.
- **PostgreSQL 16+**, reachable via a `DATABASE_URL`. See [Getting PostgreSQL](#getting-postgresql).

## Quick start

```sh
corepack enable pnpm
pnpm install
cp .env.example .env.local   # then set DATABASE_URL
pnpm db:migrate              # apply the migrations in drizzle/
pnpm db:seed                 # load the reference data in data/seed/
pnpm dev                     # http://localhost:3000
```

The home page shows live row counts from the database (49 recipes, 148 foods, …) when everything is connected.

`.env.local` is never committed. Only server code reads `DATABASE_URL`, and it's validated at startup (see
`src/server/env.ts`).

## Getting PostgreSQL

Any PostgreSQL 16+ works. Pick one.

**Docker Compose.** `compose.yaml` runs just Postgres:

```sh
docker compose up -d
# DATABASE_URL=postgres://flan:flan@localhost:5432/flan_dev
```

_Not yet verified: the development container has no Docker._ In this setup `flan` is the container's superuser, which
is fine for a throwaway local database.

**An existing install.** As a superuser, create a non-superuser role that owns the database:

```sql
create role flan login password '…';
create database flan_dev owner flan;
```

**Neon.** A Neon dev branch will be an option once the managed database is chosen (milestone M2b).

## Scripts

| Script                        | What it does                                                                                   |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `dev` / `build` / `start`     | Next.js development server / production build / serve the build                                |
| `lint` / `typecheck` / `test` | ESLint / `next typegen` + `tsc` / Vitest. These, `format:check` and `build` must pass.         |
| `format` / `format:check`     | Prettier: write / check                                                                        |
| `db:generate`                 | Generate a SQL migration from changes to `src/server/db/schema.ts` (review it, then commit it) |
| `db:migrate`                  | Apply pending migrations. Never use `drizzle-kit push`.                                        |
| `db:seed`                     | Validate and load `data/seed/*.csv` into an empty database                                     |
| `db:reset`                    | **Local only**: drop everything, migrate, seed                                                 |
| `db:checksum`                 | Per-table content checksum of the reference data (see `data/seed/README.md`)                   |
| `db:studio`                   | Drizzle Studio, a browser UI for the database                                                  |

The `db:*` scripts read `DATABASE_URL` from the environment, else from `.env*` files. A variable set inline wins, e.g.
`DATABASE_URL=… pnpm db:checksum`.

## Project layout

```
src/
  app/              routes (App Router; Server Components by default)
  components/       app components; ui/ holds shadcn/ui components (Base UI primitives)
  domain/           pure TypeScript business logic (from M2)
  server/           server-only code: env validation, db/ (schema, client, seed), queries/
drizzle/            committed SQL migrations, generated by drizzle-kit
data/seed/          reference data (the only way reference data changes)
```

## Developing in an isolated container

The project is developed in a container without Docker, with ports 3000, 8000 and 7777 mapped to the host. There,
PostgreSQL 16 comes from apt with two clusters:

- `main` on 5432 holds `flan_dev` for this app (`pg_ctlcluster 16 main start`);
- `legacy` on 5433 is the legacy app's database, used as the parity reference.

`pnpm dev` binds to all interfaces, so the app is reachable from the host at http://localhost:3000. The legacy app runs
on port 8000 (assessment §4.4).
